# CLI common workflows verification plan

Revised: 2026-09-14. Internal verification contract for the common-workflows
mitigations. This plan is not a claim of exhaustive coverage or release qualification.

The [pre-mitigation plan](agent_common_workflows_verification_test_plan_pre_mitigation_20260914.md),
original dated findings report, and original raw evidence are preserved unchanged.
Use the [verified review](../reports/agent_common_workflows_findings_review_20260914.md) and
[implementation plan](../reports/agent_common_workflows_mitigation_plan_20260914.md) for the
finding dispositions. The retained implementation runner is
[verify_common_workflows_mitigation_20260914.py](../reports/verify_common_workflows_mitigation_20260914.py).

## Product contracts and required assertions

- Search: a nonblank query and a positive integer limit are required. The default
  is 20; positive limits above 100 are capped, not rejected. Both modes reject
  invalid CLI arguments with exit 2, empty stdout, and argument diagnostics on
  stderr. Direct service validation remains in force. Runtime/source failures
  remain exit 1. A valid no-match query succeeds with complete zero bounds.
- Search responses from both modes now contain `mode`, `query`, `total`,
  `returned`, `count`, `truncated`, `bounds.results`, and `results`. Ranked
  metadata is mode-specific. Preserve substring ordering and meaningful query
  whitespace. Assert mode against the executed request, not a guessed schema.
- Queue: require integer limits in 1–1000; default 30. Reject malformed CLI
  limits with exit 2 before capture. Assert `schema_version`, `limit`, `total`,
  `returned`, `omitted`, and `items`; `returned == len(items)` and
  `total == returned + omitted`. Item fields include `path`, `classification`,
  `score`, `reasons`, and `ownership`. Do not require the old plan's invented
  `count`, `page`, or `actionable` keys. The adopted additive `limit` metadata
  stays in v1 and is part of `queue_id`. Unknown freshness remains explicit.
- Context: exact v3 requests require a trusted counter; CLI callers provide a
  local tokenizer and the optional tokens dependency. Missing or estimated
  counters do not produce exact-success results. Independently recount the
  complete emitted text, including the final newline, with the pinned local
  tokenizer. Require recount <= `accounting.used_tokens` <= budget and an exact
  compliance label only in exact mode. Legacy allocation accounting and v3
  complete-output accounting have different scopes; do not confuse them.
- Cross-format comparisons use actual text footers or item header lines, not
  invented numbered queue rows. Different formats need not contain identical
  fields. Only compare applicable common semantics with saved observed values.
- Tests for review, api-diff, and doctor must cite their current owning tests and
  version-specific output contracts before their historical oracles count as
  verified. A zero exit code alone cannot establish semantic correctness.

## Execution and evidence requirements

Use the project `.venv/bin/python` and `.venv/bin/pytest`. The small reproduction
fixture is generated by the retained runner; it contains one Python source,
106 search matches, a wiki index/log, and a synthetic local tokenizer. It uses
no external helper downloads. Unit regressions cover empty/exactly-full queues,
service type validation, whitespace-sensitive substring matching, and sentinels
proving rejection before dispatch/capture.

Record commit, dirty status, changed-source hashes, executable/import path,
package/Python/tokenizer versions, platform, immutable fixture recipe/content
hashes, exact argv, expected/actual return codes, raw stdout/stderr, durations,
and named semantic assertions. Save pre/post file digests, mtimes and directory
membership. Save both repeated executions and compare their result/output hashes.

Every measured check has an explicit outcome. Use `unverified` for platforms,
partition-write measurements, or whole-workflow semantics not measured, and
`not-applicable` for checks irrelevant to that vector. A setup failure is
inconclusive for the intended workflow and must never be counted as a semantic
pass. Do not prefill all quality dimensions with true. Do not infer process
writes from changes in root-filesystem free space shared with other processes.

Serialize context, queue, test suites, builds, and other heavy gates. Context has
no jobs override; use jobs 1 on supported interactive extractor commands. Stop
on resource-capacity failures and mark unfinished checks inconclusive.
No agent delegation is required for this bounded verification.

Derive aggregates from execution records. Distinguish execution count from case
count and unique defects. The historical run had 86 cases, 78 marked passes,
eight marked failures, and seven catalog entries; it did not prove seven unique
bugs. Three CLI validation gaps and three separately adopted clarity/metadata
improvements are the current implementation scope. Exact-mode rejection remains
correct. Do not overwrite historical outcomes with post-fix expectations.

| Cases | Required result | Evidence owner |
|---|---|---|
| Search limits 0, -1, -5, noninteger; both modes | CLI exit 2 before dispatch | `tests/test_search_rank.py`, subprocess stream tests |
| Blank, spaces, tabs/newlines, Unicode whitespace | CLI exit 2; preserve nonblank strings exactly | `tests/test_search_rank.py` |
| Search default, 1, 100, 101, 150 with >100 matches | Accurate cap, ordering, mode, totals and truncation | Search tests and retained runner |
| Valid no-match query; both modes | Exit 0; complete zero bounds and mode | Search tests and retained runner |
| Queue -5, 0, 1001, 1000000, noninteger | CLI exit 2 before capture | Queue tests and retained runner |
| Queue 1, 30, 1000; empty, full, truncated corpus | Correct limit and total/returned/omitted counts | Queue tests and retained runner |
| Queue same corpus/limit, then different limit with same items | Stable repeated identity; distinct identity for distinct limit | Queue identity regression |
| Exact flags and v3 request file without tokenizer | Expected exit 1; no successful result/capture | Retained runner and existing counter tests |
| Exact flags and v3 request file with local tokenizer | Exit 0; pinned counter and independent recount | Retained runner; existing three-format tokenizer tests |
| Explicit estimates and mismatched/estimated exact counters | Honest estimated label; retain exact-mode rejection | `tests/test_context_budget.py` |
