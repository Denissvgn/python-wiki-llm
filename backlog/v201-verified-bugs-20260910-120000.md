## VB-05: Keep unresolved operations out of resolved flow routes

**Reproduction and impact.** A static `GET /v1/items` fixture bootstraps
successfully and commits the surface, knowledge, and manifest files. Changing
the decorator to `@app.get(f"{PREFIX}/items")` produces an operation with
`path=None` and an explicit unknown-path reason. That uncertainty is legitimate.
`attach_routes_to_entry_points()` nevertheless copies the operation into
`entry.routes`; artifact validation then rejects `routes[0].path`.

Fresh bootstrap exits 1 and leaves generated Markdown without the three native
metadata artifacts. This also occurs without `--api-contracts`. Sync from a
valid baseline exits 1 and preserves the prior metadata trio, but changes wiki
content before failing; it is not a whole-wiki rollback. The recorded evidence
lists the changed paths. The reported `observability_alerts` source produces
the same unknown-path operation in a bounded extraction.

**Implementation boundary.**

- [api_contracts.py:1860](../src/llm_wiki_cli/services/api_contracts.py#L1860), `attach_routes_to_entry_points`.
- [bootstrap_runtime.py:4949](../src/llm_wiki_cli/services/bootstrap_runtime.py#L4949) and [sync_cmd.py:3588](../src/llm_wiki_cli/commands/sync_cmd.py#L3588), shared attachment consumers.
- [extraction_service.py:2153](../src/llm_wiki_cli/services/extraction_service.py#L2153), deep-extract output.
- [wiki_surface_index.py:334](../src/llm_wiki_cli/services/wiki_surface_index.py#L334) and [knowledge_artifacts.py:1392](../src/llm_wiki_cli/services/knowledge_artifacts.py#L1392), the persisted contract.

**Fix plan.**

1. Define the resolved-route projection at the shared attachment boundary.
   Include only operations whose concrete path and method are known and valid
   under the existing route contract. Check method-unknown metadata as well as
   null/empty values; a nonempty sentinel is not evidence of a resolved method.
   Normalize optional operation IDs consistently with their contract.
2. Retain unresolved operations and their reasons in the API-contract and
   diagnostic evidence. Keep the handler flow even when it has no concrete
   route to attach. Omit the optional route field when no route is resolved;
   do not invent a path such as `/<unresolved>` or remove the handler.
3. Preserve exact-handler matching and leaf-name ambiguity checks. Filtering
   invalid routes must not make two distinct handler identities appear to be
   one unambiguous leaf name. Preserve concrete routes on mixed known/unknown
   handlers and authoritative OpenAPI routes linked to dynamic source handlers.
4. Keep the artifact validator strict. Use one attachment policy for bootstrap,
   sync, deep extract, and related graph consumers, rather than independent
   sanitizers that silently disagree. Check the projection before it reaches
   page/artifact publication so supported unknown syntax does not cause late
   self-rejection.
5. Exercise recovery from an already interrupted bootstrap and from a failed
   sync. Refresh through supported commands after the fix; preserve authored
   prose and the existing manifest-last commit/integrity rules.

**Acceptance checks.**

- F-strings, dynamic expressions, unknown methods, and router prefixes retain
  explicit uncertainty and never introduce null/sentinel resolved routes.
- Literal routes, root routes, multiple decorators, repeated mounts, hidden
  routes, aliased handlers, and authoritative OpenAPI linking still work.
- Bootstrap and sync succeed on the provided fixture both with and without the
  optional API-contract page. A valid native trio is committed; strict artifact
  validation accepts the result and no resolved route is fabricated.
- Exercise bootstrap to first sync, no-cache sync, and forced knowledge rebuild;
  require unchanged artifact bytes and mtimes when inputs have not changed.
- Keep negative validation tests for malformed stored route records. Document
  actual failure/recovery behavior; do not claim whole-tree atomicity merely
  because the three metadata files stayed unchanged.

## VB-07: Resolve Python imports within justified import roots

**Reproduction and impact.** Two unrelated nested `logging.py` files, each
containing `import logging`, become mutual import-time dependencies. An API
module importing the standard library acquires edges to both. The load-order
renderer emits an actual indeterminate cyclic group. With the eight reported
source files, the four reported logging utilities reproduce that cycle.

The defect is broader than an isolated `path.stem` assignment:
`_suffix_candidates()` also registers `logging` and `utils/logging` for nested
paths. Detailed dependency observations already call multiple candidates
`ambiguous`, while the legacy graph promotes those candidates to asserted
import-time edges. A unique wrong nested candidate is also unsafe, so removing
only multi-target edges is insufficient.

**Implementation boundary.**

- [imports.py:53](../src/llm_wiki_cli/services/imports.py#L53), `ModulePathResolver.build`, `candidates`, and `import_candidates`.
- [imports.py:287](../src/llm_wiki_cli/services/imports.py#L287), suffix aliases and relative/absolute candidate formation.
- [dependencies.py:100](../src/llm_wiki_cli/services/dependencies.py#L100), `_resolve_internal_targets`, and the graph/observation builders.
- Resolver consumers in extraction, entity relationships, TypedDict inheritance,
  legacy migration, module maps, and native dependency queries.

**Fix plan.**

1. Separate exact module identities from convenience search aliases. Resolve
   Python relative imports from the importing package path. Resolve absolute
   imports against the selected source root and justified package/import roots,
   not every suffix of every file in the repository.
2. Reuse captured source/package metadata where available. `PackageInfo.root`
   provides a project boundary; the inventory's `package` value is only a name
   and is not a complete Python import-path model. Carry necessary scope
   evidence through shared resolver inputs, without rescanning the repository
   for every import. Do not hard-code `services/<name>` as the only layout.
3. When import-root evidence is insufficient, retain ambiguity/unresolved
   evidence instead of asserting an unrelated target. Keep possible candidates
   separate from confirmed dependency edges, including in the legacy graph.
   Preserve genuine multi-file package behavior for other language families.
4. Protect standard-library imports from nested-file aliases while honoring
   genuine local shadowing and explicit relative/qualified imports. The probe
   confirms that a top-level `logging.py` can legitimately be imported as
   `logging`; a blanket stdlib-name exclusion would break that case. Reuse the
   version-compatible stdlib knowledge in
   [dependencies.py:1056](../src/llm_wiki_cli/services/dependencies.py#L1056) rather
   than unconditionally accessing `sys.stdlib_module_names` on Python 3.9.
5. Thread the same decisions through graph edges, detailed observations,
   reconciliation, module maps, cycle detection, and load order. Check indirect
   consumers so a page renderer or imported-symbol fallback cannot recreate
   rejected aliases. Keep old uncertainty visible during artifact refresh.

**Acceptance checks.**

- Nested `logging.py`, `json.py`, `types.py`, and similarly named helper files
  cannot hijack unrelated stdlib imports. No false logging SCC or cycle warning
  appears in the fixture or the reported four-module subset.
- Local root shadowing, sibling relative imports, package-qualified imports,
  package initializers, `from package import child`, `src` layouts, and explicit
  shared-library imports continue to resolve where justified.
- Equal names under separate application roots stay separate. Absent scope
  metadata and unresolved candidates never become unconditional edges.
- Review tests that currently codify global suffix matches and ambiguous
  candidates as graph edges; replace their expectations with explicit scope
  cases. Preserve the distinction between coupling and import-time edges.
- Retain Go module-root resolution, Haskell declared modules, TS/JS family
  grouping and tsconfig aliases, selected-source boundaries, and previous
  TypedDict and legacy-migration regressions.

**Coverage owners.** `tests/test_imports.py`, `tests/test_dependencies.py`,
`tests/test_dependencies_external.py`, `tests/test_module_maps.py`,
`tests/test_python_typed_dicts.py`, and `tests/test_migrate.py`.

## VB-06: Respect Python bindings in both call resolvers

**Reproduction and impact.** Without an unrelated definition, `set()` is a leaf
with no file target. Adding `service_b/cache.py:def set(key, value)` changes it
to an internal call and adds that service to the traced modules. Both
`resolve_call_edges()` and `resolve_call_observations()` reproduce this result.
The reported permissions-to-balance-cache edge also reproduces from the actual
source subset.

Related probes establish that the problem is not limited to builtin names:
an unimported `helper()` binds to an unrelated definition, and
`from external_sdk import Client` binds to an unrelated internal `Client` when
the declared import module has no match. These belong to the same binding
correctness ticket.

**Implementation boundary.**

- [extraction_service.py:2622](../src/llm_wiki_cli/services/extraction_service.py#L2622), `_resolve_call`.
- [extraction_service.py:2733](../src/llm_wiki_cli/services/extraction_service.py#L2733), `_resolve_call_observation`.
- [extraction_service.py:2384](../src/llm_wiki_cli/services/extraction_service.py#L2384), `_resolve_import_candidates` and imported-symbol indexes.
- `_edges_for_file`, `_call_observations_for_file`, workflow calls, entry-point
  tracing, data-flow projections, and native call-query consumers.

**Fix plan.**

1. Share the Python binding decision between legacy and detailed resolution.
   Preserve verified local declarations, import aliases, and `self`/`cls`
   methods. Account for callable parameters and local bindings that shadow
   builtins; an unknown parameter named `set` is not necessarily the builtin.
2. Resolve unshadowed builtin calls as file-less leaves using existing schema
   kinds. Do not add a new `builtin` kind without auditing/versioning all its
   consumers. Keep call-site arguments and source locations.
3. Remove the unscoped global-name fallback for Python calls lacking a valid
   binding. Being in the same service or package does not itself bind a name
   from another Python module. Preserve language-specific rules for languages
   where same-package cross-file calls are valid.
4. Require imported internal symbols to match their declared module using the
   VB-07 scope policy. An empty module-candidate result must not fall back to a
   globally unique class or function name. Leave unproved external bindings
   external/unresolved and preserve justified ambiguity.
5. Verify both call representations and their consumers together. Preserve
   VB-03's distinct display identities and VB-02's body-call workflow rules;
   fixing diagram labels alone does not remove a false internal target.

**Acceptance checks.**

- Test `set`, `dict`, `open`, `len`, `id`, `type`, and `format` against unrelated
  homonyms, including one and multiple candidate definitions. The other service
  must not become a callee, caller-query result, or touched module.
- Local and explicitly imported builtin-name shadows still bind correctly.
  Parameters, assignments, aliases, closures, and uncertain runtime rebinding
  must not be mistaken for an unshadowed builtin or unrelated global symbol.
- Unbound nonbuiltin calls and external imports with internal homonyms stay
  unproved; genuine imported/local/self/cls calls and recursion remain valid.
- Run matching legacy/detailed observations, entry-point flow, data-flow,
  relationship, and native caller/callee query checks. Keep raw calls and
  truthful coverage; do not implement the previously excluded call-pruning
  feature as a side effect of this fix.

**Coverage owners.** `tests/test_extract.py`,
`tests/test_extract_data_flow_details.py`, `tests/test_data_flow.py`,
`tests/test_bootstrap.py`, and `tests/test_typed_graph_queries.py`.
