## VB-08: Preserve callable identity in compact flow labels

**Reproduction and impact.** For `Builder(long_arguments...).build()`, Python
extraction retains both `name="build"` and the full attribute expression.
Both call representations correctly leave the method on the returned object
unresolved, with no file target. The separate `Builder(...)` call is internal
when that class binding is known.

The flow presentation uses the entire expression as its participant, message,
and step label. Mermaid text is then capped at 160 characters, cutting off
`.build`. The same problem affects the sequence diagram and data-flow diagram.
Two calls ending in `.build` and `.finish` can consequently display the same
text despite retaining distinct participant IDs. The full method expression
and arguments remain available in Call data and Static analysis gaps.

The named `build_recovery_report` source and the reported generated page both
reproduce the issue. A short `Builder().build()` control retains the method;
an unknown parameter factory reproduces the long-label failure too.

- [bootstrap_runtime.py:2497](../src/llm_wiki_cli/services/bootstrap_runtime.py#L2497), `_flow_actors`, `_flow_interactions`, and `_flow_data_display`, own shared flow display labels.
